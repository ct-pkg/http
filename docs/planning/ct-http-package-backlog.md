## 2. 逐条

### 1) 包身份字段

- **为什么需要**：包清单现在只有 `name` / `version` / `ldflags` / `requires`，装到哪个 store、
  由谁发布都表达不了；消费端也没法按发布者校验。这是本包对外可追溯性的缺口。
- **要做什么**：`ct.pkg` 增加 `publisher = ct` 与 `ns-root = .`。
- **前置条件**：包管理器能从索引读到发布者标识之后；在此之前写进去只是无效字段。
- **验收方式**：
  - `grep -c '^publisher = ct$' ct.pkg` 输出 `1`；`grep -c '^ns-root = \.$' ct.pkg` 输出 `1`；
  - `ct get <本地目录 spec>` 退出 0，且包确实落在 store 目录；
  - `ct install` 打印的 `-I` 指向 store，不再指向 `vendor/`。
- **现状**：工作区已有这两行但未提交（见 §4）；本轮不落地。

### 2) 安装测试改断 store 路径

- **为什么需要**：`test/gates/p10_install.sh` 现在把 include 根写死成 `-I vendor/http`。
  一旦安装根换成 store，这条测试要么假绿、要么无谓失败，不能反映真实布局。
- **要做什么**：断言 `ct install` 打印 `ct build`，并断言 `-I` 指向 store 目录；删掉 `vendor/` 断言。
- **前置条件**：包管理器把 store 目录作为 include 根之后。
- **验收方式**：
  - `grep -c 'vendor/' test/gates/p10_install.sh` 输出 `0`；
  - `bash test/gates/p10_install.sh` 退出 0，输出 `install ok` 与 `200`；
  - `test -d <store 目录>` 退出 0。
- **现状**：脚本仍有 5 处 `vendor/` 断言（第 13、77、78、79、85 行）。

### 3) 去手算 include 路径

- **为什么需要**：`test/`、`tools/` 里手拼 `-I vendor/`，路径形态一变就要全改，而且容易与
  安装输出不一致；应改为读取安装输出或 lock。
- **要做什么**：删除手写路径，改用 `ct install` 打印的行，或让构建默认读 lock。
- **前置条件**：包管理器把 store 目录作为 include 根之后；建议同时等构建默认读 lock 之后再做，
  免得再从输出字符串里拼路径。
- **验收方式**：
  - `grep -rn -- '-I vendor/' test tools` 零命中（退出 1）；
  - 全仓零命中是目标；历史卡片与评审记录里保留了旧契约原文，是否一并改写见 §5；
  - `bash tools/check.sh g0 … g9` 结果不受影响。
- **现状**：`test/` + `tools/` 共 5 处，全部在 `test/gates/p10_install.sh`。

### 4) 阻塞清单与发布说明收口

- **为什么需要**：0.1.0 的阻塞项与对外发布口径必须有本仓唯一的一处落点，读者才不会两头找。
- **要做什么**：`issues/` 覆盖 HTTP-1…HTTP-5，每条有状态、证据与结论；对外发布说明在本仓固定落点。
- **前置条件**：无（属文档责任）。
- **验收方式**：
  - `ls issues/HTTP-{1,2,3,4,5}.md` 五件齐全；
  - 每件含 `status`、证据与结论；
  - 对外发布说明有固定文件（建议 `docs/release-notes.md`）。
- **现状**：本仓有 [HTTP-1](../../issues/HTTP-1.md)、[HTTP-2](../../issues/HTTP-2.md)、
  [HTTP-3](../../issues/HTTP-3.md)；**HTTP-4、HTTP-5 本仓尚无该条正文，需自行补齐**。
