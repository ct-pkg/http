# PH-8 / T3 红证：生命周期

```text
baseline: 96794e6
命令: bash test/run.sh p8-lifetime
原始输出: ok p8-lifetime (ASAN clean)
退出码: 0

命令: bash test/run.sh p8-lifetime-bad
原始输出:
test/run.sh: line 117:  8736 Abort trap: 6           ASAN_OPTIONS=detect_leaks=0 "$tmp/$task" > "$tmp/$task.out" 2>&1
ok p8-lifetime-bad (ASAN rejected the stale request pointer)
退出码: 0
green: 实现后两命令均退出 0；正例输出
`url_ok 1 mode 1 status 200` / `cleanup_after_send 0` /
`cleanup_after_res_free 0 responses_freed 1` / `cleanup_after_req_free 1`
```

正例在基线即绿：phase 2 起 `send()` 就没有释放请求。这是**回归守卫**，不伪造红。

负例是红证的另一半：`p8-lifetime-bad` 主动做旧设计下「send 后继续用请求」的那次访问
（`http_request_release(req)` 之后读 `req->url`），ASAN 必须报 `heap-use-after-free`
并以非 0 退出。它在基线与实现后都应为绿（即「被拒绝」），证明正例里的 ASAN 不是空转。
