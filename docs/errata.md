# 勘误登记（errata）

- applies-to: 0.2.1

冻结原文不改。冻结判据、冻结摘要或其复核记录出现算术错误或事实错误时，只在本文件追加条目：
原文、修正值、原因与行为层证据全部留痕，历史判定（含「不计通过」）保持可追溯。

- 门禁：`bash tools/check.sh g1` 的 `g1-errata` 校验本文件（`tools/check.sh`）。
- 判据：每条 `## ERR-<n>` 有 `日期` / `对象` / `原文` / `修正` / `原因` / `行为证据` / `授权` 七项；
  `对象` 指向的文件存在；`原文` 的引文在该文件中逐字出现。
- 边界：勘误只修「判据文本 / 锚点数值」，不重判行为，不删除任何既有「不计通过」记录。

## ERR-001 E-P9-1 的请求数锚点

- 日期：2026-11-15
- 对象：`docs/phases/PH-9/card.md`（§5 E-P9-1 的核对锚点）
- 原文：`two status 200 error 0 requests 4 body_ok 1`
- 修正：`two status 200 error 0 requests 5 body_ok 1`
- 原因：第二条用例是「2 跳」链（`/redirect/2 → /redirect/1 → /final`），必然产生 3 个请求；
  夹具按累计数打印，前一例 2 个加本例 3 个等于 5。`4` 在算术上不可达，是冻结时的计数错误
  （把 2 跳误当 2 个请求）。
- 行为证据：该用例自 PH-9 实现起始终满足 `status 200` 与 `body_ok 1`；PH-9 收口按纪律记为
  「不计通过」，原文与记录均保留（`docs/phases/PH-9/closeout.md` §4.1）。
- 授权：用户 2026-11-15 指令「按项目既有的 errata 机制把锚点修正为 `requests 5`」。
